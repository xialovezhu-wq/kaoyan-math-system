# 数学本地正式加工与兼容传输的 T9 工作目录

本地编纂、正式收口和已有返回包的接收共用这些存储规则。默认只生成实际需要的本地工作件；仅用户点名外发时才准备网页 ZIP 和配套启动词。

## 开始即使用 T9

工作根目录是 `${MATH_COLD_ROOT}/`。调用仓库 `错题知识网络/scripts/math_workflow_storage.py init --date YYYY-MM-DD --batch-id 实际批次或准备ID`，使用返回的 workspace 与 temp_directory。此入口核对 T9 sentinel、卷 UUID、挂载点和可写性；磁盘不可用时保留现状并报告，不回退系统盘，也不创建假的挂载目录。

输入/输出 ZIP、提示词、下载原件的工作副本、解压树、网页历史副本、inventory/plan、格式适配副本、草稿、合并稿、payload、工作脚本、备份、日志和检查报告都放在本次 T9 目录。各命令输出和 `TMPDIR` 指向该目录；不再用仓库 `planning/`、`网页交付/` 或 `/tmp` 存这些中间成果。

数学分包器的内层 quick-pack 默认存入 T9 `传输缓存/outbox/`。增强接收入口传 `--workspace-root 本次T9工作目录`，其默认工作区也在 T9。该入口只把经核验且用于正式摘要的不可变引用证据放入本地 `错题知识网络/个人知识点索引/source_cache/A增强证据/`，保持正式查询和发布可用。

分包与 A→C 交接的 `--output` 必须指向已核验 T9 的 `03_数学/` 子树；现有兼容链接可以继续使用，入口先解析真实目标并校验卷身份。本地冷产物路径和外盘不可用均明确失败，不回落到本机。分包、接收和交接的临时解压/快照目录同样位于 T9。

每个已完成产物（含内层 quick-pack、分包计划、ZIP/提示词/目录、增强输入和 A→C 交接）经校验后自动调用 `../Study-Storage-Map/cold_storage.py` 的 `register_tree` 更新本地文件级定位表及 SHA-256 回执；幂等重用也补登记。不得仅依赖迁移当天的静态索引。手写 payload、合并稿、日志等没有自动接入的文件，完成并关闭文件后也必须通过该入口以 `subject=math` 和实际用途登记，不为登记搬动正式热数据。

本地保留正式题卡、稳定显示图片、知识点完整页和短摘要、索引、事实账本、提交回执、必要的不可变正式引用证据及轻量归档指针。这些是正式运行数据；不得搬空仓库、删断引用、改哈希或用符号链接绕过校验。旧工作副本被摘要引用时，先通过正式维护将引用绑定到可靠证据并读回，或明确保留该精确成员。

## 入库后必须完成归档

原始 Capture 继续走原生 `archive_conversation_package.py` / `archive_legacy_evidence.py` 的 T9、显示闭环、Obsidian locator 和指针合同，本规范不替代它。

本批 closeout、全部相关摘要接收及本地查询核验完成后，必须检查并统一归档本批所有中间文件，包括仍在 Downloads、旧网页交付目录、planning 或 Bridge outbox 的对应副本。使用 `math_workflow_storage.py archive --source 原路径 --destination T9目标目录 --remove-local`：先复制、核对每个文件大小和 SHA-256、重新打开目标及清单、写轻量回执并持久化/读回共享定位表，再清理仍与归档一致的原字节。登记失败不得清理源文件。尚有正式引用的精确成员用重复 `--keep 相对成员路径` 保留。目标冲突或源文件变化时停止清理，不先删后拷。

整理现存历史时，以真实完成回执限定已完成批次；未完成、恢复中或其他学习会话仍依赖的资料保持可恢复，不能为清理关闭或重放学习。旧路径缺失时先查 `../Study-Storage-Map/README.md` 和文件级定位表，再核对 `数学一回滚复习系统/中间文件归档回执/`，定位 T9 原件，不重做已经完成的网页加工。冷工作文件归档不包括正式摘要、题卡、题图、当前学习队列、原生查询缓存和运行依赖，这些继续留在本机。

最终说明实际 T9 目录、归档范围、清理字节及因正式引用/活跃状态保留的项目。只复制成功不等于本地已清理。原始包或中间文件归档未完成时，单列待补步骤，只恢复归档，不重新 apply、计错或接收摘要。
