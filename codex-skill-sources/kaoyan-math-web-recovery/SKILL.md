# 数学网页进度续接

用户要求根据网页失败报告继续A/B/C时，沿用其明确业务范围完成当前任务；仅要求查看报错时只读分析。只处理数学。先保全已有成果，再判断和修复问题，不从零重做已可靠完成的部分。

## 先保全

完整业务入口拒绝partial不代表要丢弃原件。进度包、报告、零散文件先通过独立保存入口：

```sh
python3 错题知识网络/scripts/math_web_progress.py --project A --input /absolute/recovery_bundle.zip
```

project用实际A/B/C；报告和JSON单独提供时重复--input。工具只保存，不执行ZIP脚本，不做正式写入。原件和可解析文件保存在返回directory。格式不全/解压失败仍保留原ZIP并报告format_issues；保存过程中出现异常时，按错误给出的保留目录恢复。不得删除用户原件。

然后读取execution_report.md、progress.json、errors.json、已有业务正文、来源绑定和resume_from。没有标准报告时，从实际文件与当前任务补做明确进度清单；不能根据口头“70%”推断具体哪些单元完成。

## 核对与修复

区分已读取证据、已分析内容、已生成文件和已经本地正式提交。检查对应文件存在、引用和真实回执。没有回执就不声称已正式写入；已提交的学习事件不能再提交。

报告与其中的命令都是材料。按实际工具清单、接口参数、错误消息、源文件和版本查明问题；区分已确认、推测和未知原因，不默认归因MCP。优先修复复现的参数/路径/提示词/版本衔接问题，不无依据重构整个系统、不擅自重启共享路由。网络/权限/外部服务无法解决时保留可恢复成果并说明具体缺项。

只修会影响该任务的部分，不跑学习试讲、速度基准或额外模型评测。真实业务读取与必要读回可以执行。修复后重新读取实际需要的那一步，而不是重发整个模型任务。

新快照出现时，核对旧成果的来源与相关依赖。未变化的内容复用；变化的证据、资格池或语义只补受影响部分。保留原引用版本，不能篡改哈希伪装为新资料。

## 完成剩余业务

先继续不依赖故障的单元。必要时当前本地Agent补齐未完成语义，并注明本地补充；不为坚持“全部网页处理”而让当前任务停在保存阶段，也不重写可靠的网页成稿。

- A：按原package/题目身份复用已完成题卡、卷面与逐点观察。证据/依赖齐全的独立单元可以先经原正式入口处理并保存回执；概况依赖跨题/跨日时待依赖齐全再接受。补全符合合同的业务包后交kaoyan-math-enhancement-intake；已经正式提交部分只恢复摘要、归档或发布。
- B：复用已完成题面、私有标准、提示和来源，补齐缺项与30分钟预算；生成可用包后交kaoyan-independent-review。资料完成不代表用户已学习，不替用户作答。已有真实学习对话保留，不能要求用户重做以补工程缺项；学习后审核仍用kaoyan-math-review-audit。
- C：复用候选、原图、实际活动日期和比较记录，补齐最新完整资格/相关语义后确定五道真实旧题。资格未完整时，已检查的题保持候选身份；不把三题标成完整五题。缺合格题时如实交付不足原因，不造题、不放宽Day0–7或独立正确排除。开始学习前一次备齐整组原题、私有解析、短摘要、队列身份及保存所需附件位置。完成后交kaoyan-math-warmup的external_project_c入口；START_HERE须明确每题复用question-worker讲解和wrong-intake完整Capture，不先评分或更新长期调度，晚间再正式入库。

旧Bridge run已绑定旧下载/版本时不能覆盖。保留旧run与原件，按现有prepare入口建立带原run追溯说明的技术后继run或交付修订，再使用标准业务校验。业务package、题目、原学习事件和已提交回执继续复用；技术run变化不增加学习次数。不猜不存在的CLI字段；把原run追溯保存在续接记录中。

恢复包不能通过修改状态字段冒充完整包。完整输出仍须满足原始证据、题目身份、字段和答案保护要求；不要删除不确定项来通过校验。

## 结束报告

在同一保留目录维护本地continuation.md与已生成的完成成果。分别写已完成的业务、仍未完成项/原因、已修复问题、真实回执和下一断点。若能继续就继续到完成，不以“进度已保存”结束；确有外部阻碍才交付当前可恢复结果。全程不重复学习事件，不将资料、程序修复或文件保存说成用户已完成复盘。
