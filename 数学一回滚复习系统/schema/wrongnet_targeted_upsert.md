# Wrongnet 单题定点同步合同

本文件规定正式数学错题卡与长期复习单元之间的单题同步边界。实现入口是：

```bash
python3 数学一回滚复习系统/scripts/scheduler.py upsert-wrongnet --id GS-xxx
```

## 身份与作用域

- 请求 ID 必须匹配 `GS-数字`、`LA-数字` 或 `PR-数字`。
- 正式卡必须在 `错题知识网络/错题卡/` 中按该 ID 唯一命中，且 frontmatter `id` 必须一致。
- 目标单元必须是 `unit_id_from_card()` 生成的规范 WQ 单元，同时满足 `类型: 错题` 和 `关联错题ID` 一致。
- 其他同 `关联错题ID` 的方法模板或聚合单元不是目标，不得修改。
- 单元不存在时创建；存在时定点更新。禁止为一题运行 `sync-wrongnet` 全库同步。

## 允许字段白名单

已有单元做普通元数据同步时，只允许从正式卡更新：

- `模块`
- `内容名称`
- `知识点`
- `错因类型`
- `难度等级`
- `重要程度`
- `源错点`
- `源卡状态`
- `定点同步状态`

身份字段只校验，不静默改写。普通元数据同步必须保留 `复习方式`、`备注`、`掌握度`、`错误次数`、所有历史字段，以及现有阶段、间隔、上次日期和下次日期。错题卡中的 `review.next` 和 `review.interval_days` 不能覆盖长期调度器的现有状态。

## 正式做错事件

复发证据只来自 `wrong_history`，不能使用标题、来源、录入日期、更新时间、宽泛知识点或 `method_gap.repeat_count` 推断。

一条可处理事件必须同时具备：

1. 唯一明确的日期。
2. 明确做错语义，例如“第 2 次错”“再次做错”“复发”“无法启动”或“选错方法”。
3. 稳定事件身份。已处理事件的内在 ID 始终使用“错题 ID + 日期 + 第 N 次错”；`rollback.event_id` 只认证当前最新事件，并作为声明 ID 附着到调度历史，不能替换内在 ID。

“第 3 次接触，复做基本做对”等成功记录不是做错事件。`mistake_count` 增加但没有对应明确事件、新事件出现但计数未增加、已处理事件消失、源计数回退或事件日期晚于运行日期时，全部失败关闭。

纯成功、否定失败记录，例如“没有再次做错”“确认未复发”，不构成事件。若同一行开头已经明确写出“第 N 次错”“首次做错”“无法启动”或“选错方法”，该失败事件仍保留，即使后半句补充了当日纠错结果。

预防性提醒，例如“避免再次做错”“防止出错”“容易犯错”，也不构成复发事件。若 `mistake_count` 因此增加但不存在对应的明确失败记录，定点命令失败关闭。

已有单元第一次接入定点协议时，如果卡片中的历史事件日期都不晚于单元已有的 `最近复发日期`，这些事件只用于建立已处理基线，不追溯重置今天的调度。没有 `rollback` 明确声明时，自动识别的新复发必须发生在本次运行日期，并且晚于已有标记。

旧单元首次接入新协议时，第 1 次错只建立基线，不触发复发重置。没有声明事件 ID 时，只有运行日当天、序号至少为 2 且晚于现有复发标记的明确事件，才自动视为本轮新复发；同日迁移必须另有计数证据。仍有歧义时不得猜测。

本轮正式入库明确声称新增复发时必须加 `--expect-recurrence`。若找不到唯一新事件，命令以 `回滚同步未完成` 退出。

## 正式卡 rollback 声明

`rollback` 只描述最新一条需要与定点调度器衔接的正式事件：

```yaml
rollback:
  event_id: GS-906-20260716-2
  event_date: 2026-07-16
  event_type: recurrence
  same_method_gap: false
  method_gap_evidence: ""
```

- `event_id` 在当前错题内必须稳定且唯一。
- `event_date` 必须能在 `wrong_history` 的明确做错事件中找到。
- `event_type` 只能是 `wrong` 或 `recurrence`，也接受等价中文值。
- `same_method_gap: true` 时必须提供具体 `method_gap_evidence`。
- 普通首次错或纯元数据同步可以不写 `rollback`。

后续再次复发时，`rollback` 会改为描述新的最新事件；已经处理的旧事件仍保留原来的内在 ID，不会因为最新声明变化而被判定为删除或重新累计。
如果 `wrong_history` 已新增更晚事件，但 `rollback` 仍指向旧事件，命令失败关闭；陈旧声明不能被套到新的方法断点复发上。
`method_gap_evidence` 必须是调度器实际解析到的非空文本；`>-`、`|` 等尚未解析的 YAML block scalar 标记不算证据，建议在 frontmatter 中写成单行引号字符串。

## 方法断点复发门禁

知识点相同、章节相同、宽泛错因相同或 related 边相同，都不能证明同一方法断点复发。

只有以下条件同时成立，`同方法断点复发次数` 才增加：

1. 本轮存在一条新的正式做错事件。
2. `rollback.same_method_gap` 明确为 `true`，并有具体证据。
3. `method_gap.enabled` 为 `true`、`confidence` 为 `high`、`need_user_confirmation` 为 `false`。
4. 当前方法触发、第一动作、漏掉动作、动作类型和方法卡形成的指纹，与上一源版本已保存的指纹完全一致。

首次见到方法断点时只建立指纹基线，不直接宣称“同方法断点复发”。任何方法断点聚合只写当前目标单元中的有界计数，不顺带修改其他错题。

## 幂等与历史保护

`定点同步状态` 保存：

- `源版本`：对白名单元数据、正式做错事件、源做错次数、rollback 声明和方法断点指纹生成的 SHA-256。
- `源做错次数`。
- `已处理错题事件ID`。
- `当前方法断点指纹`。

相同源版本重复执行返回 `noop`，不写文件、不增加复发次数。正文排版、答案或其他不在同步白名单内的内容不会构成源版本。

确认复发后，`调度事件历史` 追加事件 ID、证据、源版本，以及重置前的日期、间隔、掌握度、优先级、状态、阶段和连续成功次数。原 `备注`、既有历史成绩和 `复习记录.jsonl` 不删除、不重写。

## 状态转移

新建单元或确认复发后：

- 当天只完成即时纠错，不计长期成功。
- `调度策略版本` 为 `wrongnet-targeted-v1`。
- `调度优先级` 为高风险时设为 `高`。
- 复发时 `复习状态` 设为 `复发待延迟复做`。
- `延迟复习阶段` 和 `连续延迟成功次数` 设为 0。
- `当前间隔天数` 设为 1，`下次复习日期` 设为运行日次日；该日期表示本次复发暴露的错点 anchor 从次日开始到期，不表示次日直接投递复发原题。
- 复发时 `错误次数` 和 `复发次数` 只按新事件安全增加一次。

活跃错点状态是从正式历史和作答证据计算出的派生视图，不由定点 upsert 删除历史来维护。目标日前近 7 天内的正式做错 occurrence 可以成为活跃 anchor；若更晚的可验证正式独立作答达到 4～5 分，并能证明同一具体错点、同一动作断点，或两张正式卡共同持有同一个 `knowledge` 标签，只把对应 occurrence 从派生活跃集合中移除。一次明确绑定该 anchor 的 `knowledge_fallback` 通过也适用，但不证明同一方法断点、不推进长期阶段。正式卡的 `wrong_point`、`wrong_history`、复发计数、`调度事件历史` 和历史成绩保持不变。提示后完成、不稳定作答、解析路线、自由文本粗章节或来源版本无法认证的旧事件不得自动消除 occurrence；新的正式做错事件可以重新激活。

活跃错点窗口与实际交付题的 7 天去重窗口互相独立。到期 anchor 不因交付去重而消失，但实际交付题必须是唯一正式入库且当天至恰好第 7 天没有活动，第 8 天起才可投递；anchor 原题也不能绕过该门禁。新增、做错、复做、评分、入选/投递和更新都算活动。交付卡无需预先拥有长期复习单元；只要正式卡身份与来源版本通过校验即可参与，评分仍只写 anchor 单元。精确错点、第一错步或 `method_gap` 匹配优先；没有精确候选时才允许按两张正式卡共同持有的 `knowledge` 标签使用正式旧题作为 `knowledge_fallback`，共同标签可较宽泛，但不得由自由文本章节临时推导，也不得只凭弱关系分或解析路线凑题；不得据此增加 `同方法断点复发次数` 或声称同一用户错因。候选不足时少出，不生成、改写或合成数学题。

代理题评分写入 anchor 单元只是调度事实，不能把 anchor 的 `上次复习日期` 当成原卡实际活动。交付去重必须按实际 `delivered_card_id` 归属；近期 occurrence 已被正确覆盖但长期阶段仍到期时，使用独立的 `formal_due_proxy_exact` 或 `formal_due_proxy_knowledge_fallback` 身份，不能计入最近七天活跃错点统计。

正式评分只用于到期后的独立闭卷检查。晨间队列通过 `score-warmup` 提交：`exact_gap` 或直接到期检查可以按长期规则推进 anchor 单元；`knowledge_fallback` 做对只消除对应派生活跃 occurrence，不增加长期成功次数或推进长期阶段。任何模式都不顺带修改交付题对应的其他单元。下表仅描述 `exact_gap` 与直接到期检查的长期状态转移：

| 评分 | 语义 | 阶段与下次间隔 |
|---|---|---|
| 0～2 | 做错、无法启动、选错方法或依靠明显提示 | 阶段与连续成功清零，次日再做 |
| 3 | 独立做对但明显不稳定 | 不推进长期阶段，最多 3 天短周期 |
| 4～5 | 独立闭卷做对并完成方法辨认 | 连续成功增加，按 3、7、14、30、45 天推进 |

`knowledge_fallback` 的 0～3 分保留该活跃 occurrence；4～5 分只把这次知识点级检查记为已覆盖，长期阶段和连续延迟成功次数保持不变。

复发当天或尚未到期时提交评分会被拒绝，该到期门禁适用于新旧所有长期单元。当天即时纠错不调用 `score`，也不追加长期复习日志。新评分日志写 `attempt_type: delayed`、`attempt_id` 和 `event_id`，历史日志保持原格式。同一评分事件重复提交返回 `noop`；冲突结果失败关闭。

## 考试期限

唯一权威入口是 `学习进度.json` 顶层 `exam_date`。不从相对天数推导考试日期。

- 当前权威值为 `2026-12-20`。配置缺失或无效时，纯元数据同步可运行；任何需要产生新日期的创建、复发、warmup 或 score 都失败关闭。
- 距考试超过 30 天，使用正常阶段间隔。
- 距考试 15～30 天，高风险题最大 7 天，其他不稳定题最大 14 天。
- 距考试 14 天及以内，稳定题不再推进新的长期阶段，也不自动拉入最后一周；不稳定题保留 1～7 天短周期。
- 计划会越过考试时，稳定低风险题暂停自动排期；历史高风险题可在考前 14～21 天保留一次代表性检查。
- 任何非空 `下次复习日期` 不得晚于考试日期。

`下次复习日期` 只决定错点 anchor 何时开始到期，不直接指定实际交付题；`调度优先级` 只决定到期 anchor 超过每日 5 道时的先后顺序。

## 写入与失败语义

写入前先对整份账本做兼容性结构校验，对目标新增字段做严格校验。旧数据允许额外历史字段、可空下次日期和历史掌握度类型，不借本次操作全量迁移。

写入使用持久锁文件、同目录临时文件、flush、fsync、重新解析与校验、源文件版本复核、`os.replace` 和目录 fsync。`upsert-wrongnet`、`score`、`add` 与 `sync-wrongnet` 的账本写入都必须携带读取时的版本；旧批量写入口不能拿过期快照覆盖定点状态。源文件被其他进程修改、替换失败或任何门禁失败时，临时文件清理，原 JSON 保持完整，命令报告对应的未完成状态。

定点 upsert 不读取或写入 `复习记录.jsonl`，也不修改 `学习前5题记录.jsonl`。
